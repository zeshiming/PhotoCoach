# PhotoCoach Agent Loop

## 1. 已确认的输入模式

PhotoCoach 是单 Agent，但会先理解用户目标和所需能力，再选择处理路径：

### 模式 A：纯文字摄影咨询

用户只发送文字，例如：

> 我只有手机，怎么拍出电影感？

Agent 应该：

1. 判断用户目标和所需能力，是摄影知识回答、图片理解、拍摄规划还是图片生成。
2. 如果是摄影问题，直接根据摄影知识回答。
3. 如果用户明确需要生成图片，再进入图片生成流程。
4. 用户没有要求生成图片时，不主动生成图片。

### 模式 B：文字 + 图片分析

用户发送文字和照片，例如：

> 这张照片为什么人物脸比较暗？

Agent 应该：

1. 读取用户问题和图片。
2. 根据任务理解结果调用图片理解能力。
3. 区分图片事实和摄影建议。
4. 结合用户设备、水平和拍摄目标回答。
5. 支持用户围绕同一张图片继续追问。

### 模式 C：纯图片输入

用户只上传图片、没有文字时，Agent 不应该猜测用户想解决什么问题。它应先做简短概览，并追问用户想了解什么，例如：

> 我可以帮你分析构图、光线、曝光、色彩或后期方向。你最想先了解哪一部分？

## 2. 单 Agent 处理流程

```text
接收用户消息
  ↓
判断是否有文字、图片
  ↓
理解任务并识别所需能力
  ├─ clarify → 返回澄清问题
  ├─ refuse → 返回拒答
  ├─ answer → 进入回答层
  └─ plan → ToolExecutor 选择并执行工具
  ↓
读取工具 observation
  ↓
生成最终回答或重新规划
  ↓
检查是否符合摄影边界和用户要求
  ↓
返回回答并保存本轮对话
```

## 3. 当前已实现的 SDK 闭环

当前代码已经支持：

```text
Agents SDK Agent
  ↓
Runner
  ↓
Pydantic Tool Schema
  ↓
GLM-4V-Flash Function Tool
  ↓
最终回答
```

当前主入口已经使用 OpenAI Agents SDK；`MockImageAnalyzer` 和旧的自定义 AgentLoop 仍用于测试和对比。真实图片分析由 GLM-4V-Flash 完成。

## 4. 为什么要先理解任务

同样是摄影相关的文字，用户可能想要不同结果：

- “怎么拍”是知识或拍摄建议；
- “分析这张照片”需要视觉理解；
- “帮我生成一张……”才需要图片生成。

如果不先理解任务，Agent 可能在用户只想咨询时错误生成图片，也可能在需要分析图片时只给泛泛的摄影知识。

## 5. 当前版本边界

V0 先实现：

- 纯文字摄影咨询；
- 文字 + 图片分析；
- 纯图片输入后的追问；
- 多轮上下文记忆。

图片生成先记录为意图分支，放到后续版本实现。这样第一版可以先验证单 Agent 的对话、视觉分析和上下文逻辑。
